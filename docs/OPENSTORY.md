# OpenStory 红楼梦推演移植

依据 ZJU-LLMs/OpenStory `3e4857a07ec141a9ed6d3be586dd5d3c573ae389` 的 `examples/story_of_the_stone/story`，Apache-2.0。许可与原文件哈希见 `third_party/openstory/`；发布版保留许可证。

## 已接入的流程

| 上游机制 | 大观园实现 |
| --- | --- |
| BasicPlanPlugin 长期目标、时辰计划、动态重排 | `server/openstory.mjs` 的改编提示词；每人保存一次性目标、最多六步计划、重要性和反思；每步两小时，知情变化/任务变更/计划完成后重排 |
| BasicInvokePlugin 重要性占用、轮流对话 | `src/simulation/openstory.ts`；现有三维路径实际到达后会面，每人每步最多参与一次；各自感知，最多四轮自由对话，可拒绝和提前结束 |
| BasicReflectPlugin 结果、记忆和复兴评分 | 结构化叙事、参与者记忆、未决问题、反思；安定 -10/0/+10，财力与关系有界变化，未参与者不得被改动 |
| 分支、快照、回溯 | 沿用已有世界线，一整步原子保存；模型失败、取消或非法结果均不提交半步；故事记录与计划随分支恢复 |

移植至现有 TypeScript/Node 技术栈，未部署上游 Redis/Ray 服务。原项目固定第80回、12时辰整日计划、最多10轮对话改成当前版本/起点、最多6个后续时段、最多4轮，以适配浏览器和服务器请求预算。没有复制上游的模型密钥、人物数据集或像素前端，也不靠对白中的死亡关键词直接删除人物。

## 三种版本

- `original80`：前八十回范围，80回后保持开放，不预定续本结局。
- `cheng120`：程高本，已审核的97/105回起点提供独立背景，不能混入癸酉走向。
- `guiyou108`：癸酉本，已审核的82/90/91回起点提供独立背景。依据有争议的公开回目，不能宣称收录了完整续文或证实为曹雪芹原稿。

三者都运行同一完整推演流程，传入各自版本边界、起点回目与人物私有记忆，分别存档。共同早期起点的事实本来相同，不为制造版本差异提前注入未来结局。全文覆盖范围仍以 `data/canon/editionCatalog.json` 的 coverage 为准。

## 使用

世界推演 → 故事推演 → 启用故事模式，填写既有推演访问口令。选择人物后可以自然语言托付任务，再点继续故事。事件卡展示新情节、原始对话、状态结果和后续问题。本地规则保留为无需模型的行为演示，界面明确区分；模型失败不悄悄切换演示模式。

故事结果为模型在约束内裁决的虚构事件，不是原著证据。人物判断可能出错、计划可能受阻，文本事实质量仍依赖模型；数字仅是游戏设定。没有新增尚未建模的角色，也未实现任意物品/建筑/婚姻等复杂物理系统。新事件会存入记忆影响下一步，不只是事后续写摘要。

存档保存最近30步，当前世界最多40个故事结果。浏览器存档可导出；不会把生成内容写入 canon。`npm test` 覆盖事务回滚、个人知情、占用、三版本、分支恢复及结果边界；`npm run test:openstory:model` 是需 LLM_* 环境的真实模型验收，使用模拟场景执行器，不冒充浏览器动画测试。
