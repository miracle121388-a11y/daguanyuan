# 连续故事推演

主界面的“生成下一段故事”直接调用服务器模型，不再使用本地规则或预设对白。原有行为演示代码保留供回归测试与旧存档兼容，不在主推演入口提供切换。上游借鉴与许可保留在代码注释和 third_party/openstory，产品界面不显示框架名称。

一次续演包括：模型创作 → 模型复核前后文一致性 → 校验结构及舞台地点 → 展示可用的三维镜头 → 原子保存。每次将累积故事档案、最近三段正文、未决线索、用户方向和 IF 条件重新传入模型。人物仅获得模型列明由其亲历或获知的事实；生死状态保存，已经死亡的角色禁止在后续恢复。更早段落可从最多30个时间快照中读取或恢复，导出存档包含这些内容。

## 原文输入与范围

- 三种版本各自保存，默认以各版本实际已有的审核节点作为起点，不能将零散资料谎称为完整80/120/108回。
- 内置原文库为数字汇校本的80回和120回阅读范围；未导入私人原文时，创作及复核都会检索所选回目的最后6000字符和此前相关段落。该检索不等于模型已经通读两份TXT，也不是独立程甲刻本校勘。癸酉本全文缺失，不以程高本代替。
- 在“原文与续演起点”设置原文截至的回数，导入 TXT/Markdown（UTF-8 或 GB18030，不超过5MB/150万字）。应只包含对应版本截至该回的内容。检测到后续回标题时拒绝读取。
- 原文按不超过16000字符分块，由真实模型合并为最多10000字符的累积故事档案；保留最后6000字符原文供准确衔接。每一块都读取，显示进度，可取消。仅全部成功后保存；原文哈希、字数、文件名、摘要和尾段随存档保存。全文本身不在浏览器持久化，也不写入公开 canon。
- 原文会发送至项目配置的模型服务。长文读取需要多次模型调用，时间和费用随长度增加。摘要压缩会损失细节；未实现完整全文逐句检索，不保证长篇细节无遗漏。
- 未上传完整八十回时，只能称为基于已核对节选的续演。这里验收的原文读取样例是明确标注的人造短篇前情，不能宣称完成“全八十回”质量验收。

## 创作与三维的界限

叙事可以包含其他人物和园外事件，三维只节选已有四个人物、已有场景的可执行动作。正文的事件推进不再受原动作枚举限制。数据结构校验和第二次模型复核能减少时间倒退、知情越界等问题，但文学合理性仍需阅读判断，不能声称推得作者唯一原意。生成内容始终是独立创作。

`npm test` 覆盖主按钮真实请求路径（HTTP mock）、连续记忆、人物知情隔离、版本范围、IF、取消回滚和原文全分片读取；`npm run test:continuation:model` 是配置 LLM_* 后的真实模型验收，不默认在普通测试中产生费用。
