# 代理访问排查

本站运行于现有 California 服务，入口为 https://daguanyuan-rumeng.zeabur.app/ 。网页、模型、纹理和接口均为同源资源。

2026-09-24 本机 Clash Verge 开启 TUN、规则模式。系统 DNS 返回 `198.18.0.234`，这是 fake-IP 占位，不能据此认定公网 DNS 错误。最初经域名连接在 TLS 握手阶段失败，尚未进入网页。公开 DNS 查询返回 `47.89.212.251`；保留域名和证书校验、以该地址建立连接则成功。

针对本站添加 DIRECT 后可返回 200，但国内直达 California 的线路较慢：`overview-low.glb` 的压缩传输为 2,867,205 字节，20 秒只收到 542,106 字节。继续测试本站的解析覆盖并保留原有代理组后，同一资源完整下载约 3.38 秒。这些是本机单次观测，不是所有网络的性能保证。

本机修复只对本站域名设置 Clash hosts 映射，并在当前订阅前置规则中保留原有代理组。没有修改 Windows hosts、系统 DNS、代理节点、其他域名规则或关闭 TLS 校验。原配置备份保存在不入库的 `.checkpoints/proxy-site-20260924/`。此映射适用于当前服务器；迁移服务或域名解析变化时必须先核验新的公开 DNS，再更新或删除该域名映射，不能沿用旧地址。切换其他订阅也需重新检查分流配置。

验证命令：

```powershell
$env:GARDEN_TEST_PROXY='http://127.0.0.1:7897'
npm run test:network
```

该检查在普通浏览器和显式 HTTP 代理下打开实际网站，等待完整三维场景，检查健康接口与资源错误，保留桌面和触摸模拟截图。它不固定浏览器 DNS、不关闭 HTTP/2 或 HTTP/3，也不跳过证书验证。HTTP 握手失败发生在应用之前，修改 React 页面不能修复该类故障；应先检查解析、代理线路和 TLS，再检查页面与资源加载。
